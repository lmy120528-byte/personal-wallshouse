# 七选（SevenPick）项目介绍

## 项目定位
七选是一款宝宝养育助手 Agent（早期为奶粉消费决策 Agent，2026-09-15 起弱化奶粉推荐、转向养育助手）。由张强一个人 0→1 打造：2026 年 6 月立项，2026 年 10 月上线微信小程序，全程约 8 周。

## 立项与需求
1. 立项：宝爸的真实痛点——「货架上有几百种好，却没人回答我的宝宝适合什么」；
2. 需求一句话：「几轮对话，给我家宝宝一个答案」。

## 产品设计：三层架构
1. 用户画像层：先接情绪再问信息，7 个字段由 LLM 并行提取；
2. 匹配层：硬规则 + LLM 打分，推荐结果可追溯；
3. 供给层：知识图谱——淘宝 API 采集 869 个 SKU，品牌归一化（48 个品牌 → 14 个品牌 / 45 个系列），最终 323 个可推荐 SKU，双层图谱 Graph RAG，数据可信度分层。

## 开发与技术
1. 约 2.1 万行全栈代码：FastAPI + Vue3/Vant + DeepSeek + SQLite；
2. H5 + O 端管理后台；
3. 上线形态：微信小程序「七选」（2026-10-12 审核通过正式上线）+ H5 公网版 https://www.sevenpick.com.cn/；
4. 线上稳态响应约 38 秒（Agent 多轮推理）。

## 评测体系（自建 Eval）
1. 六维评分卡：安全合规 25%（一票否决）/ 因果链 22% / 排名 18% / JSON 15% / 体验 10% / 诚实 10%；
2. 30 道题、5 条链路，LLM-as-Judge，约 16 分钟自动跑完一轮；
3. 六轮迭代 79 → 90 → 89，当前 89 分、零 badcase。

## 过程中的亮点故事
1. badcase 定位：早产儿推荐差，根因不在 LLM 而在候选层（MCT 配方被 Top8 截断挤出）→ 保送修复，同题 3 分升到 4 分；
2. P0 生产事故：异步路由同步调用 LLM 没有超时设置导致全站卡死；修复 = 线程池隔离 + 150 秒超时；
3. 提审止损：web-view 套壳方案个人主体不支持，提前核查官方文档省下返工周期；
4. 60 分原则：每层做到能跑就往下走，不恋战。

## 做这个项目的三个动机
1. 真实痛点：自家宝宝养育的真实需求；
2. GEO 模式验证：实践「在 AI 回答里被引用」的增长方式；
3. AI Product Builder 自我证明：验证产品经理用 AI 工具独立完成全栈产品的能力。

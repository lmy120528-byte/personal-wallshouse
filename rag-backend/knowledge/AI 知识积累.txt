## AI应用
在AI应用的中，技术迭代大抵可以分为4个方向
- 查询层：让模型能给更好的听懂人话，或者说让人能说出给能让模型理解的内容：诸如prompt优化、上下文工程、skills等，都是在这个方向上做功的‘；
- 执行层：让模型更好的理解人类的知识沉淀，知道该从哪里找到内容回复用户，并且能够做出动作，诸如RAG、知识图谱、MCP等，都是在执行这层做功的；
- 模型层：大模型自身的能力，诸如多模态、参数训练等等，偏技术了，总之是让模型的基座能力更强大，逻辑推理与理解能力更强；
用户需求——》模型——》动作（回复 or 执行）

## 吴恩达课程感悟
《AI for everyone》-23.22 课程有感
对于某个垂直领域的AI产品，优势在于生成正向循环的数据飞轮；
切入某个场景，通过AI能力在这个场景下满足需求带来价值，越来越多的人使用，然后产生新的数据，去优化AI能力；
这个循环的优势在于自己产生数据,迭代AI能力，逐渐加深壁垒，这是竞争力；
举例：
一个创业团队，农业领域，机器自动化除杂草，让要机器能自己识别哪些事白菜、哪些是杂草；
起初是自己拍很多农田的照片，标注出哪些是白菜、那些事杂草，让机器学习识别出杂草；
有一定效果后，让农民去用这个机器，然后在除草机后面挂上个摄像机，不断地识别不同农田下的杂草和白菜的区别，让除草机识别的越来越准；
越来越多的农民去用，可识别的图像数据越来越多，除草机识别的越来越准，这么多数据对机器学习的积累是竞争壁垒，即使是大公司进入，短时间内也很难抢占市场；

# AI概念理解
##  自主规划Agent与工作流Agent
1. 工作流智能体（低自主智能体）基于预设流程执行的AI系统，按照预定义步骤顺序完成任务，强调确定性和可控性。通常是通过编排工作流实现的，预设好某一步意图识别、某一步调用工具等；
2. 自主规划Agent（高自主智能体）具备主动目标理解、路径规划和决策能力的AI系统，在给定框架和约束下，能自主探索解决方案；
实现方式
1. 工作流Agent意图识别——》流程选择——》步骤执行——》结果返回关键组件
  - 意图分类，识别用户的意图，后续该走什么分支；
  - 流程引擎，执行预设工作流；
  - 工具调用，根据意图分类的结果和顺序，调用MCP工具；
  - 模板输出，按照格式化输出结果；
2. 自主规划Agent目标理解——》框架选择——》自主规划——》动态执行——》结果生成关键组件配置重点
  - 系统提示词：设定行为框架和行为准则
  - Skill系统：模块化能力封装
  - 工具集：提供基础能力
  - 规划器：自主执行路径
  - 验证器，确保结果质量
  - 思维框架设计（系统提示词）
  - 能力模块划分（skill设计）
  - 工具粒度设计
  - 自主边界设定
  - 质量评估机制
3. 应用场景工作流agent自主规划Agent
  - 当场景覆盖的范围可以枚举，任务流程固定且可枚举时，输出结果需要高度一致性，对错误率的容忍度较低；
  - 希望解决的问题具有探索性和不确定性，需要创造性解决方案，有足够的数据支撑分析，追求深度洞察而非简单方案；

##  MCP与skill差异
关于 Agent Skill 与 MCP 的差异，以下是我的理解。MCP 更多是一个协议机制，它是给模型去连接外部协议的一个工具，它相当于是接口一样，让模型有了做事情的能力。而 Skill 它更多的是在特定场景下的一部分任务描述，这个任务既包含涉及到外部协议与外部工具的地方，也包含不涉及到外部工具的地方。
我举个例子，以电商场景的智能客服 Agent 为例，比如解决一个用户申请订单价保这样的一个能力。那么其中涉及到的 MCP 就会有很多，比方说查询订单是否可以申请价保，以及查询订单购买时的商品金额、可退还的差价，以及查询相应的规则条件，最终返回一个结果：能否申请价保，以及可能给用户退多少钱。这是需要诸多 MCP 接口才能够给模型实现的这个能力。
而 Skill 的话，可能是对于这一个场景的一个封装。比方说当用户要申请价保的时候，那么你可以通过以下这些方式去执行：第一步，调用某一个 MCP 接口去查询这个订单能否申请；第二步，查询他购买时的金额；第三步，查询相关的协议；第四步，调用退还的这部分接口的能力。把这一整个封装成了一个 Skill，让这个 Agent 具备对于申请价保这个场景的这部分能力。
以上是 Skill 对于需要向外部协作、需要通过外部工具调用的封装。也包含 Skill 不需要这种外部工具调用的封装，比方说我给他描述一个帮我写 PRD 的场景，那么可能我告诉他背景、过程、整个文档的结构、关键点需要怎么写，那这个其实是不需要调用 MCP 的，只是针对我的描述出发的一个场景，然后让模型来约束这个场景下的任务与具体行为。
总结下，这两者不是一个维度的东西，mcp 是给了模型调用外部工具的能力
skill 是教会模型在某个场景的特定任务下做事的方法，其中包括涉及 mcp 调用的场景，也包括不涉及 mcp 的场景。

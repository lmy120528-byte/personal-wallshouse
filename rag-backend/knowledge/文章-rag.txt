# RAG 是什么，有什么用途
> RAG 全名 Retrieval（检索）Augmented（增强）Generation（生成），检索增强生成技术。
> 是结合了信息检索和语言生成的技术，当模型需要回答问题的时候，它会先从一个文档集合中，检索出相关的信息，然后利用这些检索到的信息来指导文本生成，从而提高预测的质量和准确性。

# 为什么需要有 RAG 技术
RAG 的出现主要为了解决通用大模型在实际落地应用中的几个核心痛点：
- 静态知识的局限：大模型训练完成后，其知识库就固定了，训练模型的数据是固定的、历史的，对于实时更新的信息（如新闻、股价）或企业内部未公开的私有知识，模型无法获取。
- 模型的幻觉问题：大模型有时会生成看似合理但不符合事实的 “幻觉” 答案，需要外部资料帮助模型验证生成内容的合理性。
- 落地专业领域下的模型可用性：通用大模型的训练数据赋予了它通用的逻辑理解与回答能力，但不具备行业专业性。想让大模型精通某个专业领域（如法律、医疗），传统方法需要耗费大量算力和数据对模型进行 “微调”，成本高且可能导致原有能力遗忘。

# RAG 技术的原理
简单理解就是在问模型问题时，给模型一段文档，让模型参照这个文档回答问题。
- 当需要给模型的文档越来越长、越来越多时，模型难以高效查找，随即衍生出文档切片（chunking）技术。切片后对每一小段文字进行embedding（向量化）（通过某个模型），将切片后的文字转化为一个个多维坐标数字。用户的问题也会转为向量坐标数字，根据坐标的远近，模型找到对应的切片内容，再将用户的问题与检索到的内容一起给到模型，由模型生成回答。
- 将切片后的内容向量化后，需要进行向量存储，即将文字内容与向量坐标对应起来并存入向量数据库。传统数据库是ID+内容，向量数据库是向量坐标（数组）+内容。
- RAG 的关键是内容的处理压缩（即切片→向量化），但这种切片技术也存在缺陷：可能会因为模型对内容的理解不够充分导致切片位置错误，或在压缩过程中丢失重要内容（切片损失）。
总结来说，**RAG 技术的流程是：将文档【切片】→【编码（向量化）】→【存储】，文档内容通过以上 3 步存储在向量数据库中等待检索。当用户提出问题时，先将问题用同样的 embedding 模型进行向量化，然后从向量数据库中找到位置相近的内容，最后把问题和挑选出的内容一起给到模型生成答案。**

# RAG技术的弊端
将文档切片向量化后，不可避免的会损失文本的全局结构、实体间的复杂关系和深层的逻辑链条，模型检索到的可能只是“语义相近”的片段，对于全局问题和局部片段的问题匹配度太低；
在做设计RAG结构时，其中重点就是**设计向量化的切片策略**
切片太粗 → 检索精度低，返回一堆不相关的内容
切片太细 → 语义不完整，关键信息被拆散
切错位置 → 本该在一起的信息被拆到两个切片里
**切片的本质不是技术问题，是信息架构问题。**
## 三种切片策略
- 策略 1：固定长度切片，每 N 字切一刀，不管内容结构。
    - **适用**：长篇小说、新闻流水账
    -  **不适用**：内容围绕某个主题，上下文有语义关联的内容；
- 策略 2：按标题层级切片（结构感知），以 `##` 二级标题为切片边界，每个二级标题下的内容是一个独立切片。
>  比如原文结构：
>  GEO 行业格局分析
> ## 一、四类服务商（500 字）
> ## 二、两端一连接框架（800 字）
> ## 三、未来趋势判断（600 字）
切出来
>  切出来：
> 切片 1: "## 一、四类服务商" + 500 字  ← 语义完整
> 切片 2: "## 二、两端一连接框架" + 800 字  ← 语义完整
> 切片 3: "## 三、未来趋势判断" + 600 字  ← 语义完整
- **优点**：每个切片语义完整，标题本身提供上下文
- **缺点**：如果某个标题下内容过长（2000+ 字），切片太大影响检索精度;
- 策略 3：递归语义切片,将文本递归地分成小块，每次在"语义最不相关"的地方下刀。
   分隔符优先级：段落分隔（两个换行）> 单换行 > 句号 > 逗号 > 空格
- **适用**：无结构的自由文本
- **不适用**：需要严格结构的场景
可根据文档类型与内容结构，做混合策略；
## 切片效果验收
**人工验证（定性）**
可以准备10个典型问题，手动验证：
1. 每个问题 → 跑检索 → 看返回了哪些切片
2. 判断标准：
   ✓ 切片内容能完整回答这个问题 = 切得好
   ✗ 切片内容缺关键信息，明显在另一个切片里 = 切坏了
   ✗ 切片内容混杂了不相关的内容 = 切得太粗
**脚本验证（定量）**
验证脚本跑以下指标：
1. **切片数量分布**：有没有过长（>2000 字）或过短（<50 字）的切片？
2. **专属匹配率**："怎么看 GEO 未来？" 是否主要匹配到 GEO 文章，而非AI科普相关文章？
3. **相关性打分**：用 LLM 给每个检索结果打 1-5 分

# RAG 检索知识与模型训练知识的区别
RAG 的外部文档，是给模型用于回答的参考内容；而大模型本身是处理和生成答案的 “大脑”。
训练模型的知识是固定的、有时效性的，比如 DeepSeek-V4 训练的数据截止到 2026.5月。它提供给模型的是通用的底座能力，比如语义理解、逻辑推理、原理类固定知识（如数学原理 1+1=2）。
有了 RAG 技术，大模型拥有了更多的落地应用场景。RAG 是一种非常务实且高性价比的工程技术方案，它让大模型得以快速、安全地在企业中 **“开箱即用”**。
# 典型应用场景
- 智能客服与知识库问答：这是 RAG 应用最广泛的领域。系统可以基于企业内部的产品手册、政策文档、历史工单等，为员工或客户提供精准、一致的回答。例如，金融机构的柜员能即时查询到最新、最准确的合规政策解读。我们普通人也可以将自己积累的内容（lifelog、情绪 log、知识积累），通过开源大模型部署专属助手，它可能比你更了解自己。
- 数据分析与商业智能：将 RAG 与数据库结合（SQL-RAG），可以让人用自然语言直接查询复杂的企业数据。例如，管理层可以直接问 “上个季度华东区 A 产品的销售额是多少？”，系统会自动查询数据库并生成分析报告。
- 代码与研发辅助：企业内部可以将历史代码库、技术文档、事故报告等构建为知识库。例如，货拉拉通过 RAG 系统，让开发者在提交代码时能自动比对历史 “资损代码” 模式，有效预防线上事故。
- 专业领域智能体：在法律、医疗等高度专业的领域，RAG 可以整合法律条文、判决案例或医学文献、诊疗指南，构建出专业、可靠的辅助决策工具。
使用 DeepSeek 的联网搜索，本质上也是一种 RAG 技术，其流程为：
用户提问→识别意图，优化搜索关键词→并行获取搜索结果→将搜索引擎返回的 “原料” 进行融合处理→大模型深度加工（推理、整合、优化语言）→生成最终答案并标明来源→输出回答

Agent 比我做得好，我为什么不敢放手？

一方面，效率确实被拉上去了，一个人能并行推好几个项目；但另一方面，一种说不清的失控感越来越强烈。这篇文章想把这段时间关于"人和 Agent 怎么协作"的思考写下来。不是方法论，是一个传统产品人在范式切换期的真实阵痛。01 传统工作的安全感，是怎么被打破的传统产品经理的安全感，来自全链路的透明。洞察需求 → 规划方案 → 画 Demo → 写 PRD → 需求评审 → 研发上线。每一步我都要亲自走一遍。产品细节、数据逻辑、交互流程，我必须做到完全清楚。上线的版本要和我的 PRD 严丝合缝，出了异常我能凭经验推测大概是哪里出了问题。这种"知其然也知其所以然"的完整推导，是手艺人的底气，也是掌控感的基石。但 Agent 出现之后，这条路变了。你只需要把需求和背景告诉它，它来规划产品结构、写代码、做测试。效率是数量级的提升——一个人同时跑几个项目，人在回路里（Human-in-the-loop）做的事越来越少，甚至开始走向人在回路外（Human-out-of-the-loop）。失控感就是这个时候来的。Agent 给的结果往往非常好，甚至超出我的预期。但我缺席了中间的推导过程。我没有经历那个"前因"，我对细节不再了如指掌。如果线上出了问题，我还能给出靠谱的判断吗？更纠结的是一个悖论：要让 Agent 产出好，你得说得明白；要说明白，你得先想明白。但如果我什么都自己想透了，像传统范式一样从 0 推到 1，那不又浪费了模型的能力，丢了效率提升的机会吗？02 不是不思考了，是思考的位置变了解开这个悖论的关键，是想清楚一件事：新范式下我们不是不思考了，而是思考的维度和阶段发生了位移。用一个比喻传统 PM 是手艺人，亲自雕琢每一个齿轮，确保全流程严丝合缝；Agent 时代的 PM 更像总导演——不需要亲自打光调色，但对剧本内核、核心调性、边界红线和最终交付质量，要有绝对的判断力。那"想明白"到底在想什么？以前想的是执行路径——每个逻辑流转、数据表字段、异常分支，事无巨细自己推一遍。现在要想的是问题空间和约束条件：这个业务的本质和核心价值是什么？边界红线在哪里？（资金安全、并发防重、资损兜底）成功标准是什么？什么样的结果算"好"，什么算"不可接受"？对应到具体动作上：放下：对非核心实现路径的微观执念；对"100% 亲自推导、每个细节都要能解释"的过度追求。拿起：意图架构和边界设定；高维度的判断敏锐度和审美；反向拷问、极端测试和验收能力。从亲手做每一步，到定义好什么不能错，中间的位移就是效率释放的来源。当工具比你更熟练，你需要重新想清楚自己该站在哪里。03 人到底该做到哪一步拿"下单退款流程"这个例子说。传统范式：人凭空推导 100% 细节 → 人写 PRD 画图 → 研发写代码。新范式：人前置定义风险地图 → Agent 生成完整方案 → 人做对抗性验收。两步关键动作：前置：定义"风险地图"。在把任务交给 Agent 之前，你得想清楚业务的骨架和禁区。比如："下单退款最怕资金风险——多退、重复扣款，必须做防重防并发，第三方回调失败要有兜底。"把这些作为高维约束喂给 Agent，而不是让它盲盒发挥。后置：从编写者变成打靶人。Agent 秒级给出完整方案后，不要全盘接收。换上"极端用户"视角反问："防重复提交你是怎么设计的？底层接口延迟超过 3 秒会怎样？" "列出这个方案里最容易出 Bug 的三个极端场景，说明处理逻辑。"总结成一句话：你不需要前置想清楚 100% 的步骤细节，但要前置想清楚 80% 的业务目标和风险点；然后拿着 Agent 补全的 100% 细节，用你的经验去打靶和裁决。04 更深的不安：到底是谁在用谁想到这里，还有一个更深层的感受。过去的工具革命里，工具是人的延伸——汽车延伸双腿，计算机延伸算力，人始终是明确的主体。但 AI 和 Agent 时代，人和工具的关系好像发生了微妙的倒置。你每次向 Agent 提需求、做纠偏、写 Prompt，表面上是你在用它干活。但在宏观层面，你的专业经验、思维逻辑、甚至你纠正它的错误，都在变成喂养模型的养料。人类过去积累的经验，正在被高效地结构化、抽离、资产化到大模型里。更直接的感受是手里的本领正在变成写下来的规则。我们写的 Prompt、验收清单、评测标准、排查链路，一旦写完就不再只属于我 —— 它们可以被复制、被他人使用、被沉淀下来。这是好事，也是失去的一部分：以前「我会这个」是一种手上的功夫，现在它更像一条谁都照着走的流程。2\. 从创造者变成了审稿人。以前我享受从 0 到 1 塑造产品的成就感；现在我的主要工作，是给 Agent 的产出打分、找茬、点赞或者重试。坐在这个位置上，人确实越来越像流水线上的一个节点。3\. 人没有变轻松。门槛被压低之后，等着我的不是空闲，而是更多可以并行的事 —— 同时推几个项目、审阅翻倍的产出。效率把标准一起抬高了，人被迫像机器一样高频运转。05 怎么办：守住你自己面对这个不可逆的趋势，我的应对思路是守住三样东西：第一，搞清楚谁是雇主。AI 再强大，也只是一个没有欲望、不承担商业后果的概率模型。你才是那个连接真实世界、对结果负责的人。它给出的永远只是提案，你永远有最终的否决权。这个关系不能搞反。第二，守住"离线思考"。不要把思考本身也托管给 AI。AI 擅长穷举逻辑、找标准解，但它没有痛觉，没有对真实用户困境的体察。把机械的逻辑拆解、文档撰写、代码生成交给它；把对人的共情、对业务痛点的直觉、对审美的偏执，留给自己。具体做法：在打开 Agent 之前，先花 10 分钟拿纸笔做最核心的思考。想清楚你要什么、怕它在哪跑偏。带着这个锚点去面对 Agent，就不会被它海量但平庸的通用方案淹没。第三，从"被动质检员"变回"主动创造者"。如果你只是对着 AI 的产出打勾改错，你一定会感到异化。但如果你用 AI 省下来的时间，去做以前一个人根本不敢想的事——发起更大的项目、探索更深的用户需求——你才是工具的主人。最后说回最开始那个失控感。现在我慢慢想明白一件事：我害怕的不是不知道逻辑怎么写，而是害怕自己不再是那个"能把事情想透的人"。但回头看，我的价值从来不是"想得比谁都快"，而是知道什么问题值得想、什么结果算好、什么不能错。放下对微观细节的执念，拿起对方向和边界的判断。这不是被 AI 取代，这是换了一种更高级的工作方式。工具越来越强的时候，人最需要守住的，反而是自己最本能的东西。
